# 全双工语音通话方案（待外部条件）

> 阶段三 P2 待外部条件项。本文档为完整接入指引，**标注依赖外部 STT/TTS 实时服务**，
> 当前本地实现为**基于文件的 STT/TTS**（`VoiceChatController` + `SpeechService`），
> 尚未做到实时全双工流式通话。

## 一、现状

| 能力 | 现状 | 位置 |
|------|------|------|
| STT（语音转文本） | 一次性上传音频文件 → 同步返回文本 | `POST /api/voice/stt` |
| TTS（文本转语音） | 文本 → 一次性返回音频流 | `POST /api/voice/tts` |
| 实时全双工 | **未实现** | — |

现有链路是"录一段 → 上传 → 识别 → 回复 → 合成 → 下载播放"的轮次式交互，
存在明显延迟，无法做到边说边听、随时打断（barge-in）。

## 二、目标

- 低延迟实时语音流（端到端 < 800ms 理想）；
- 全双工：用户说话时可随时打断 AI；
- VAD（语音活动检测）自动断句，无需手动按停。

## 三、技术选型

### 方案 A：WebRTC（推荐，低延迟）

- 浏览器原生 `getUserMedia()` 采集麦克风流；
- 后端用 **Spring Boot + WebRTC**（如 `webrtc-java` / Jitsi lib 或 Janus/mediasoup 媒体服务器）转发 RTP 流；
- STT/TTS 在媒体服务侧以流式接入。

优点：延迟最低、原生支持回声消除与降噪；
代价：媒体服务器部署复杂，需要 TURN/STUN（公网穿透）。

### 方案 B：WebSocket + 音频分片（落地快）

- 前端 `MediaRecorder` / `AudioWorklet` 把麦克风流切成小分片（如 100ms 一帧）；
- 通过既有 `spring-boot-starter-websocket`（已引入）把 PCM/Opus 分片推到后端；
- 后端把分片转发给流式 STT，文本落 `ChatService`，AI 回复再经流式 TTS 合成音频分片回推。

优点：复用现有 WebSocket 依赖，不需要额外媒体服务器；
代价：延迟略高于 WebRTC，但工程上最易落地。

## 四、前端录音 / 播放方案

```text
getUserMedia() -> AudioWorkletNode(16kHz PCM)
              -> WebSocket.send(binary frame, ~100ms)
              -> 后端流式 STT -> 文本
              -> AI 流式生成（复用 SSE / Flux）
              -> 流式 TTS -> WebSocket 回推音频分片
              -> AudioWorkletNode 实时播放队列
```

关键 API：
- 录音：`navigator.mediaDevices.getUserMedia({ audio })` + `AudioWorklet`；
- 播放：`AudioContext` + 环形缓冲队列，避免卡顿；
- 打断（barge-in）：VAD 检测到人声立即清空 TTS 播放队列。

## 五、后端音频转发方案

```text
WebSocket /voice/stream (二进制帧)
   ├─ 入站：PCM 分片 -> 流式 STT SDK -> onPartialText -> onFinalText
   ├─ 处理：finalText 注入 ChatService（复用 OllamaService/ModelRouter）
   └─ 出站：AI token 流 -> 流式 TTS SDK -> 音频分片 -> WebSocket 回推
```

复用点：
- 鉴权：`AuthContext.requireUserId()`；
- 对话链路：`ChatController` 已有的角色记忆 / 上下文注入 / 配额；
- 画像：`UserProfileService.recordConversation()` 自动沉淀。

## 六、第三方 STT / TTS 集成（待外部条件）

| 环节 | 自托管选项 | 云服务选项 |
|------|-----------|-----------|
| 流式 STT | faster-whisper / Vosk（本地模型，需 GPU） | 阿里云 / 腾讯云 / 讯飞 实时语音识别 |
| 流式 TTS | Coqui TTS / Piper（本地） | 阿里云 / 腾讯云 / ElevenLabs 实时合成 |

**待外部条件**：
1. 需选定并接入一个**流式**（非文件式）STT 服务；
2. 需选定并接入一个**流式** TTS 服务；
3. 自托管方案需 GPU 推理资源；云方案需 API Key 与计费预算。

接入点预留：在 `SpeechService` 旁新增 `StreamingSpeechService` 接口，
方法签名 `Flux<String> streamSTT(Flux<byte[]> audio)` 与 `Flux<byte[]> streamTTS(Flux<String> text)`，
外部服务就绪后填实现即可，不影响现有文件式接口。

## 七、安全与合规

- 麦克风流须 HTTPS / WSS（`getUserMedia` 与 WebSocket 在非 localhost 下要求安全上下文）；
- 音频不落盘或落盘加密，遵循 `DataAccessPermission` / 隐私设置；
- 未成年人模式下禁用实时语音（参考 `user.is_minor` 标记）。
