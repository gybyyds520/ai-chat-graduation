# AI Chat 部署手册

> 适用版本：后端 `com.example:aichat:0.0.1-SNAPSHOT`（Spring Boot 3.5.16）/ 前端 `ai-chat-frontend@1.0.0`（Vue3 + Vite 5）。
> 本文档面向**生产部署 / 服务器部署**场景，本地开发请直接参考根目录 `启动AI-Chat.bat` 与 `.env.example`。

---

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | **25+** | 后端按 Java 25 编译；Spring Boot 3.5.16 支持 Java 25 |
| Node.js | **18+**（实测 22.23.2） | 用于前端构建 `vite build`；运行时仅需静态文件，不需要 Node |
| npm | 9+（实测 10.9.8） | 随 Node 附带 |
| MySQL | **8.0+** | 库名默认 `ai_chat`，要求 utf8mb4 字符集 |
| Redis | 6.0+ | 缓存与会话层（`spring-boot-starter-data-redis`），未启动会导致启动失败或缓存降级 |
| Ollama | 可选（本地模型） | 仅当使用本地大模型 / 语音对话 LLM 时需要；不部署则自动降级 Mock |
| Nginx | 1.18+ | 反向代理 + 前端静态托管（见 `Nginx反代配置.md`） |

**硬件建议**：4 核 CPU / 8 GB 内存 / 50 GB 磁盘起步；如开启本地 Ollama 模型，显存另计。

## 2. 数据库初始化

后端使用 **Flyway** 自动迁移，无需手工建表：

- 迁移脚本位置：`backend/aichat/src/main/resources/db/migration/`（`classpath:db/migration`）
- 关键配置（`application.yml`）：
  ```yaml
  spring:
    flyway:
      enabled: true
      locations: classpath:db/migration
      baseline-on-migrate: true   # 首次在已有库上自动建立基线
      baseline-version: 0
      validate-on-migrate: false
      clean-disabled: true         # 生产禁止 clean，防止误删
  ```

**首次部署只需手工创建空库**：

```sql
CREATE DATABASE ai_chat DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
```

应用启动时 Flyway 会自动执行 `V*.sql` 脚本完成全部表结构与初始数据迁移。根目录下的 `ai_chat_schema.sql`、`ai_chat_schema_v2*.sql` 为历史手工脚本，**新部署不要手工执行**，以 Flyway 为准。

## 3. 后端部署

### 3.1 打包

```bash
cd backend/aichat
# Windows
mvnw.cmd -DskipTests package
# Linux/macOS
./mvnw -DskipTests package
```

产物：`backend/aichat/target/aichat-0.0.1-SNAPSHOT.jar`。

### 3.2 生产 profile 配置

项目当前 `application.yml` 为开发默认值。生产环境请新建 **`application-prod.yml`**（建议放在 jar 同级目录或 `config/` 子目录，Spring Boot 会自动加载），覆盖以下关键项：

```yaml
server:
  port: 8443
  ssl:
    enabled: true                 # 生产开启 HTTPS，证书生成见 docs/HTTPS部署指南.md
    key-store: classpath:keystore.p12
    key-store-password: ${SSL_KEYSTORE_PASSWORD:changeit}
    key-store-type: PKCS12
    key-alias: ai-chat

spring:
  datasource:
    url: jdbc:mysql://<DB_HOST>:3306/ai_chat?useSSL=true&serverTimezone=Asia/Shanghai&characterEncoding=utf8&rewriteBatchedStatements=true
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:}

cors:
  # 生产只放行实际前端域名，不要保留 localhost
  allowed-origins: ${CORS_ALLOWED_ORIGINS:https://your-domain.com}
```

> 说明：数据库密码、JWT 密钥、第三方 API Key **一律走环境变量**，不要写进 `application-prod.yml` 提交到仓库。

### 3.3 启动

```bash
# Linux 后台运行示例
nohup java -jar aichat-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=prod \
  > logs/app.log 2>&1 &
```

```powershell
# Windows 后台运行示例（PowerShell）
Start-Process -FilePath "java" `
  -ArgumentList "-jar","aichat-0.0.1-SNAPSHOT.jar","--spring.profiles.active=prod" `
  -WindowStyle Hidden
```

启动后健康检查：`GET http://127.0.0.1:8443/api/health` 返回 200 即正常。

### 3.4 API 文档（OpenAPI / Swagger UI）

后端已集成 springdoc-openapi 2.3.0，启动后访问：

- Swagger UI：`https://your-domain.com/docs/swagger-ui.html`
- OpenAPI JSON：`https://your-domain.com/docs/api-docs`

这两个路径已在 `SecurityConfig` 中 `permitAll` 放行，Nginx 反代需将 `/docs/**` 透传至后端（见 `Nginx反代配置.md`）。

## 4. 前端部署

### 4.1 构建

```bash
cd frontend
npm install            # 首次或依赖变更后
npm run build
```

构建产物输出到 `frontend/dist/`（含 `index.html` 与 `assets/`）。构建会同时输出 modern 与 legacy 两套 bundle（`@vitejs/plugin-legacy` 兼容旧浏览器），现代浏览器自动加载 modern 版。

> 前端体积构成与优化建议见 `前端体积分析报告.md`。

### 4.2 静态托管

将 `dist/` 整体交给 Nginx 托管，并把 `/api`、`/ws`、`/uploads`、`/docs` 反代到后端。完整 `nginx.conf` 见 `Nginx反代配置.md`。

要点：

- `index.html` 必须回退到根（SPA history 路由）：`try_files $uri $uri/ /index.html;`
- `assets/` 带内容哈希，开启长缓存（`Cache-Control: immutable`）。

## 5. 环境变量清单

生产环境**必须**通过环境变量注入以下敏感配置（`application.yml` 中 `${VAR:default}` 形式读取）：

| 环境变量 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `DB_URL` | 否 | `jdbc:mysql://localhost:3306/ai_chat?...` | JDBC 连接串，生产改 `useSSL=true` |
| `DB_USERNAME` | 否 | `root` | 数据库账号 |
| `DB_PASSWORD` | **是** | 空 | 数据库密码，**不可为空** |
| `REDIS_HOST` | 否 | `localhost` | Redis 主机 |
| `REDIS_PORT` | 否 | `6379` | Redis 端口 |
| `REDIS_PASSWORD` | 视情况 | 空 | Redis 有密码时必填 |
| `REDIS_DB` | 否 | `0` | Redis 逻辑库编号 |
| `JWT_SECRET_KEY` | **是** | 随机（重启失效） | JWT 签名密钥，**长度 ≥ 32 字节**；未配置则每次重启所有 token 失效 |
| `OPENAI_API_KEY` | 视情况 | 空 | OpenAI / DALL·E / Whisper 共用 Key |
| `DEEPSEEK_API_KEY` | 视情况 | 空 | DeepSeek 模型 Key |
| `CORS_ALLOWED_ORIGINS` | **是** | 本地开发白名单 | 逗号分隔的前端来源，生产改为线上域名 |
| `IMAGE_PROVIDER` | 否 | `stable-diffusion` | 图像生成提供者：`stable-diffusion` / `openai-dall-e` / `disabled` |
| `SD_API_URL` | 否 | `http://localhost:7860` | Stable Diffusion WebUI 地址 |
| `STT_PROVIDER` | 否 | `openai-whisper` | 语音识别提供者 |
| `TTS_PROVIDER` | 否 | `google-translate` | 语音合成提供者 |
| `VOICE_LLM_OLLAMA_ENABLED` | 否 | `true` | 语音对话是否走本地 Ollama |
| `SSL_KEYSTORE_PASSWORD` | 视情况 | `changeit` | HTTPS keystore 密码 |

> 配置命名以代码实际读取为准：JWT 密钥为 `JWT_SECRET_KEY`（见 `TokenUtils.java`），AI Key 按厂商区分（`OPENAI_API_KEY` / `DEEPSEEK_API_KEY`），并非统一 `AI_API_KEY`。

## 6. 常见部署问题（FAQ）

1. **启动报 `Communications link failure` / 连接被拒**
   MySQL 未启动、`DB_URL` 主机端口错误，或安全组未放行。先在服务器本地 `mysql -h <host> -u root -p` 验证连通性。

2. **启动卡在 Flyway / `Table 'ai_chat.flyway_schema_history' doesn't exist`**
   正常：Flyway 首次迁移会自动建该表。若报迁移校验失败，确认 `validate-on-migrate: false` 已开启（已默认），不要手工改 `db/migration` 下已执行脚本。

3. **启动后所有登录请求立刻 401 / 重启后用户全部掉线**
   未设置 `JWT_SECRET_KEY`，应用每次启动随机生成密钥。设置一个 ≥32 字节的固定值即可。

4. **前端页面能打开，但接口 401 / 跨域报错 `CORS`**
   检查 `CORS_ALLOWED_ORIGINS` 是否包含实际访问的协议+域名+端口；注意 `http` 与 `https`、末尾斜杠都要精确匹配。

5. **上传文件 / 生成图片 404**
   `/uploads/**` 未在 Nginx 反代或静态目录配置中透传；确认后端 `image.upload-dir: ./uploads/generated/` 存在且可写。

6. **AI 对话长时间无响应 / 504**
   SSE 流式接口在 Nginx 反代层超时。按 `Nginx反代配置.md` 设置 `proxy_read_timeout 300s`、关闭 SSE 缓冲。

7. **WebSocket 好友/群聊消息收不到**
   Nginx 缺少 `Upgrade` / `Connection` 头透传，按反代文档配置 `proxy_set_header Upgrade $http_upgrade`。

8. **`/docs/swagger-ui.html` 404**
   确认引入了 `springdoc-openapi-starter-webmvc-ui` 依赖（pom.xml 已含 2.3.0），且 Nginx 把 `/docs/**` 透传到后端 8443 端口。

9. **中文路径 / 中文用户名下测试或打包乱码**
   Maven Surefire 已强制 `-Dfile.encoding=UTF-8`；前端构建需在 UTF-8 终端执行。Windows 下建议用 PowerShell 而非 CMD。
