# 数据库备份策略

本文档规定 AI-Chat 项目 MySQL 数据库（`ai_chat`）的备份频率、保留策略、恢复流程与监控告警方案。对应脚本：`scripts/backup_db.ps1`（备份核心）、`scripts/run_backup.ps1`（一键入口）。

---

## 一、备份概览

| 项目 | 说明 |
|------|------|
| 备份对象 | MySQL 数据库 `ai_chat`（含表结构、数据、存储过程、触发器、事件） |
| 备份工具 | `mysqldump`（InnoDB `--single-transaction` 一致性快照，不锁表） |
| 输出目录 | `<项目根>/backups/` |
| 文件命名 | `ai_chat_YYYYMMDD_HHmmss.sql`；`-Full` 模式为 `ai_chat_YYYYMMDD_HHmmss.sql.gz` |
| 字符集 | utf8mb4 |
| 凭据 | 通过环境变量 `DB_PASSWORD` 注入，不写死在脚本外的调度配置里 |

---

## 二、备份频率

### 日备（每日凌晨 2:00）

- 通过 Windows 任务计划程序每日执行一次 `scripts\run_backup.ps1`。
- 建议使用普通模式（不压缩），保留 7 天，满足常规误删恢复窗口。

创建计划任务（管理员 PowerShell 执行一次）：

```powershell
$action = New-ScheduledTaskAction `
    -Execute 'powershell.exe' `
    -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\path\to\ai-chat-graduation\scripts\run_backup.ps1"'
$trigger = New-ScheduledTaskTrigger -Daily -At 2:00AM
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -DontStopOnIdleEnd
Register-ScheduledTask -TaskName 'AIChat_Daily_DB_Backup' -Action $action -Trigger $trigger -Settings $settings -RunLevel Highest
```

### 周备（每周日凌晨 3:00，全量压缩）

- 在日备之外，每周日额外执行一次 `-Full` 全量压缩备份。
- 周备文件建议在文件名或目录上与日备区分（如手动复制到 `backups/weekly/`，或单独建一个周备计划任务调用 `run_backup.ps1 -Full` 并在脚本外归档）。

创建周备计划任务：

```powershell
$action = New-ScheduledTaskAction `
    -Execute 'powershell.exe' `
    -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\path\to\ai-chat-graduation\scripts\run_backup.ps1" -Full'
$trigger = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Sunday -At 3:00AM
Register-ScheduledTask -TaskName 'AIChat_Weekly_DB_Backup_Full' -Action $action -Trigger $trigger -RunLevel Highest
```

## 三、保留策略

| 类型 | 频率 | 保留时长 | 说明 |
|------|------|----------|------|
| 日备 | 每日 02:00 | 7 天 | `backup_db.ps1` 自动清理 7 天前的 `ai_chat*.sql*` 文件 |
| 周备 | 每周日 03:00（-Full 压缩） | 4 周 | 全量压缩归档，用于更长周期的回滚与审计 |

- 日备清理逻辑已内置在 `backup_db.ps1`：删除 `backups/` 下 `LastWriteTime` 早于 7 天前的 `ai_chat*.sql*`。
- 周备由于带压缩且归档周期更长，建议单独放在 `backups/weekly/` 目录，避免被日备清理逻辑误删；如需脚本自动清理周备，可在调度侧或后续扩展 `-RetentionWeeks 4` 参数。
- 生产环境建议额外把 `backups/` 定时同步到对象存储 / 异地磁盘，防范本机磁盘损坏。

## 四、恢复流程

> 恢复前先停掉应用（或至少停掉写入流量），避免恢复过程中产生新的脏数据。

### 1. 恢复日备（.sql）

```powershell
# 1) 确认目标备份文件
Get-ChildItem .\backups\ai_chat_*.sql | Sort-Object LastWriteTime -Descending | Select-Object -First 5

# 2) 恢复到 ai_chat 数据库（会覆盖同名库，请确认）
mysql -u root -p ai_chat < .\backups\ai_chat_20260917_020000.sql
```

或一行命令：

```powershell
cmd /c "mysql -u root -p123456 ai_chat < .\backups\ai_chat_20260917_020000.sql"
```

### 2. 恢复周备（.sql.gz 压缩包）

```powershell
# 先解压
$gz  = '.\backups\weekly\ai_chat_20260914_030000.sql.gz'
$sql = $gz -replace '\.gz$',''
$in  = [System.IO.File]::OpenRead($gz)
$out = [System.IO.File]::Create($sql)
$gzp = New-Object System.IO.Compression.GzipStream($in, [System.IO.Compression.CompressionMode]::Decompress)
$gzp.CopyTo($out); $gzp.Close(); $out.Close(); $in.Close()

# 再导入
mysql -u root -p123456 ai_chat < $sql
```

### 3. 恢复后校验

```powershell
# 检查关键表行数 / 最近更新时间是否合理
mysql -u root -p123456 ai_chat -e "SELECT COUNT(*) FROM user; SELECT MAX(create_time) FROM message;"
```

- 校验通过后再启动应用、恢复流量。
- 若误恢复到错误库名，可先 `mysqldump` 现状再操作，保留退路。

## 五、监控告警

### 1. 失败判定

`backup_db.ps1` / `run_backup.ps1` 以**非零退出码**表示失败：

| 退出码 | 含义 |
|--------|------|
| 0 | 成功 |
| 1 | 未找到 mysqldump |
| 2 | mysqldump 执行失败（MySQL 未启动 / 密码错误 / 网络问题） |
| 3 | 备份文件未生成或为空 |

### 2. 在计划任务中捕获失败

注册计划任务时增加"任务失败"触发动作，例如写入事件日志或调用告警脚本：

```powershell
# 失败时追加日志（可在此处扩展为企业微信/邮件/钉钉 webhook 通知）
$onFailure = New-ScheduledTaskAction -Execute 'powershell.exe' `
    -Argument '-NoProfile -Command "Add-Content -Path .\backups\backup_error.log -Value (Get-Date -Format o + '' BACKUP FAILED'')"'
$trigger = New-ScheduledTaskTrigger -Daily -At 2:00AM
Register-ScheduledTask -TaskName 'AIChat_Daily_DB_Backup' -Action $action -Trigger $trigger
# 在任务计划程序 UI 中：属性 -> 设置 -> 如果失败，按以下频率重启（可选）
```

### 3. 告警建议（生产）

- **通知渠道**：备份失败时通过企业微信 / 钉钉 / 飞书 webhook 或邮件通知运维。
- **告警内容**：失败时间、退出码、`backups/backup_error.log` 尾部、最近一次成功备份时间。
- **心跳检查**：每日人工或脚本检查 `backups/` 目录是否有当天新文件；若超过 24 小时无新备份即告警（避免"静默失败"）。
- **恢复演练**：每月至少做一次从备份恢复的演练，确认备份文件可用、恢复流程顺畅。

## 六、日常运维清单

- [ ] 每日确认 `backups/` 有当日 `.sql` 文件且大小非 0。
- [ ] 每周确认周备 `.sql.gz` 已生成并可解压。
- [ ] 每月做一次恢复演练。
- [ ] 证书 / 密码轮换后，同步更新任务计划中的环境变量 `DB_PASSWORD`。
- [ ] 磁盘空间不足时及时清理旧备份或扩容。
