# 前端体积分析报告

> 分析对象：`frontend`（Vue 3 + Vite 5.1 + `@vitejs/plugin-legacy`）
> 数据来源：本次 `npm run build` 实测输出（2026-09-17，vite v5.4.21，2382 modules transformed，46~101s）。
> 说明：构建同时产出 **modern**（现代浏览器）与 **legacy**（旧浏览器）两套 bundle，真实用户只下载其中一套。

## 2. 主要 chunk 分析

按 Modern 版 JS（合计 3.56 MB）占比：

| chunk | 占比 | 内容 |
| --- | ---: | --- |
| vendor-vue | **25.1%** | Vue 3 运行时 + **element-plus 全量引入** + vue-router |
| vendor-echarts | **23.6%** | ECharts 图表库（AdminView 数据看板用） |
| vendor-three | **19.9%** | Three.js（桌面精灵 3D 形象） |
| index | 17.3% | 全部业务页面代码 |
| vendor-common | 9.9% | pako、@vueuse、@mediapipe 等 |
| polyfills | 3.1% | modern polyfill |
| vendor-axios | 1.1% | axios |

**三个重量级库（element-plus / echarts / three.js）合计占 Modern JS 的约 68.6%**，是体积优化的核心。

---

## 3. 关键问题定位

### 3.1 路由未做懒加载（最大问题）
`src/router/index.js` 中所有页面均为**静态 import**：

```js
import AdminView from '@/views/AdminView.vue'      // 内含 echarts 全量
import DesktopElf from '@/views/DesktopElf.vue'    // 内含 three.js
```

这导致：
- 含 echarts 的 `AdminView`、含 three.js 的 `DesktopElf`/`AICompanion` 虽然被 `manualChunks` 拆成独立 chunk，但**仍在初始加载图内**，用户首屏就会拉取 echarts（859 KB）和 three.js（724 KB），而普通用户根本不访问管理后台和桌面精灵页。

### 3.2 element-plus 全量注册
`src/main.js`：

```js
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
app.use(ElementPlus)
```

全量引入组件库与样式，是 vendor-vue 高达 916 KB 的主因。

### 3.3 echarts 全量引入
`AdminView.vue`：`import * as echarts from 'echarts'`，引入了全部图表类型，未按 `echarts/core` 按需注册。

### 3.4 three.js 一处静态引入
`useElf3DRenderer.js` 已用 `await import('three')` 动态引入（正确），但 `components/AICompanion.vue` 仍 `import * as THREE from 'three'` 静态引入，抵消了部分动态分包收益。

---

## 4. 优化建议（按收益排序）

### 建议 1：路由级懒加载（预计首屏 JS 减少 ~40%）
把 `router/index.js` 的静态 import 改为动态：

```js
const AdminView = () => import('@/views/AdminView.vue')
const DesktopElf = () => import('@/views/DesktopElf.vue')
// 其余视图同理
```

效果：echarts、three.js 两个 chunk 从"首屏必载"变为"进入对应页面才加载"，普通用户首屏可少拉约 **1.58 MB（raw）/ 0.47 MB（gzip）**。

### 建议 2：element-plus 按需引入（预计 vendor-vue 减少 30~50%）
引入 `unplugin-vue-components` + `unplugin-auto-import`，移除 `main.js` 的全量 `app.use(ElementPlus)` 与全量 CSS，自动按需解析 `ElMessage`、`ElButton` 等组件。配合 `importStyle` 自动引入对应样式。

### 建议 3：echarts 按需注册（预计 vendor-echarts 减半）
```js
import * as echarts from 'echarts/core'
import { BarChart, LineChart } from 'echarts/charts'
import { GridComponent, TooltipComponent } from 'echarts/components'
import { CanvasRenderer } from 'echarts/renderers'
echarts.use([BarChart, LineChart, GridComponent, TooltipComponent, CanvasRenderer])
```
只注册实际用到的图表与组件。

### 建议 4：three.js 完全动态化
把 `AICompanion.vue` 的静态 `import * as THREE` 改为 `onMounted` 内 `await import('three')`，确保 three 只在桌面精灵页加载。

### 建议 5：评估 legacy bundle 必要性
当前为兼容 IE11/Android 5 等极旧浏览器，构建产出约 4.73 MB 的 legacy 副本，磁盘占用翻倍。若目标用户均为现代浏览器，可放宽 `@vitejs/plugin-legacy` 的 targets 或直接关闭，节省一半构建体积与 CI 时间。

### 建议 6：可视化分析工具
package.json 未安装 `rollup-plugin-visualizer` / `vite-bundle-visualizer`。建议二选一加入 devDependencies，后续优化可直接产出交互式 treemap：

```bash
npm i -D vite-bundle-visualizer
npx vite-bundle-visualizer
```

---

## 5. 结论

- 当前 Modern 首屏 JS gzip 约 **1.2 MB**，其中 element-plus、echarts、three.js 三大库占近七成。
- **最高杠杆点是路由懒加载**：现状静态路由把管理后台（echarts）与桌面精灵（three.js）都拉进首屏，改为动态 import 后普通用户首屏可减少约 0.47 MB gzip。
- 次优是 element-plus 按需引入与 echarts 模块化注册，二者可继续压缩 vendor-vue / vendor-echarts。
- `manualChunks` 分包策略本身合理（echarts/three/vue/axios 已独立成 chunk），主要问题不在分包，而在**静态引入导致的"被打进初始图"**。
