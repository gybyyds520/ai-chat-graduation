# 压测指南（阶段二 P1）

本文档说明如何使用 `scripts/load_test.py` 对 AI Chat 后端关键端点进行并发压测，并对结果进行解读。

## 一、压测目标

验证后端在并发访问下的吞吐与延迟表现，重点覆盖一条真实用户行为链路：

```
登录 → 角色列表（GET /api/character/list）
     → 好友列表（GET /api/friend/list）
     → 社群浏览（GET /api/community/list）
     → 聊天模拟（POST /api/friend/chat/send）
```

关注指标：

| 指标 | 含义 |
|------|------|
| QPS | 每秒处理请求数（总请求数 / 总耗时） |
| 平均响应时间 | 所有成功请求响应时间的算术平均 |
| P95 / P99 | 95% / 99% 请求的响应时间上限（长尾） |
| 错误率 | 非 2xx/3xx 与异常请求占比 |

## 二、环境准备

1. 安装依赖：

   ```bash
   pip install requests
   ```

2. 启动被测后端（确保 MySQL 已就绪）：

   ```powershell
   cd backend\aichat
   .\mvnw.cmd spring-boot:run
   ```

3. 准备一个已注册的压测账号（脚本默认 `loadtest013 / loadtest013`，可通过参数覆盖）。

## 三、运行方式

```bash
# 8 并发，持续 30 秒（最常用）
python scripts/load_test.py --concurrency 8 --duration 30

# 指定地址与账号，16 并发压测 60 秒
python scripts/load_test.py `
  --base-url http://localhost:8080 `
  --username testuser013 --password 'Test@123456' `
  --concurrency 16 --duration 60
```

参数说明：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--base-url` | `http://localhost:8080` | 被测服务地址 |
| `--username` | `loadtest013` | 压测账号 |
| `--password` | `loadtest013` | 压测密码 |
| `--concurrency` | `8` | 并发线程数 |
| `--duration` | `30` | 压测持续秒数 |
| `--timeout` | `5.0` | 单请求超时秒数 |

脚本会先调用登录接口换取 JWT，再携带 `Authorization: Bearer <token>` 压测需登录的端点；登录失败时降级为匿名压测（仅匿名可读端点成功，需登录端点会计入错误，便于发现鉴权问题）。

## 四、结果解读

脚本结束后输出示例：

```
== 压测结果 ==
总耗时        : 30.02 s
总请求数      : 4210
成功请求      : 4201
失败请求      : 9
错误率        : 0.21 %
实际 QPS      : 140.24
平均响应时间  : 52.30 ms
P50 响应时间  : 41.00 ms
P95 响应时间  : 120.50 ms
P99 响应时间  : 210.80 ms
```

判读要点：

- **错误率 > 1%**：先看错误分类。`http_401` 通常是 token/账号问题；`http_5xx` 需查后端日志与数据库连接池（HikariCP `maximum-pool-size=20`）。
- **P99 远高于平均**：存在长尾，常见于慢 SQL、AI/外部 HTTP 调用阻塞、GC 停顿。
- **QPS 随并发数不再上升**：到达瓶颈，结合 Prometheus 看 JVM 线程池、HTTP 线程（Tomcat `max=200`）、DB 连接池水位。

## 五、性能阈值建议（基线参考）

以下为本科毕设本地单机（开发机 + 本地 MySQL）的参考阈值，生产环境应按机器规格重新标定：

| 指标 | 建议告警阈值 | 说明 |
|------|--------------|------|
| 错误率 | < 0.5% | 超过说明接口不稳定 |
| 平均响应时间 | < 200 ms | 普通业务接口 |
| P95 | < 500 ms | 95% 用户体验底线 |
| P99 | < 1000 ms | 长尾可接受上限 |
| QPS | ≥ 50（8 并发） | 本地单机冒烟基线 |

> 说明：聊天接口会触发 AI 推理（Ollama/外部模型），单请求耗时天然偏高，压测时应将 AI 链路与普通 DB 链路分开观察，避免把 AI 慢响应误判为接口缺陷。
