# 向量检索优化方案（待外部条件）

> 阶段三 P2 待外部条件项。本文档为完整迁移指引，**标注依赖外部向量数据库与嵌入模型**，
> 当前本地实现为 **MySQL LIKE / 关键词重叠检索**（完全离线、零外部依赖）。

## 一、现状

知识库检索链路（`KnowledgeBaseServiceImpl`）：

```text
文档上传 -> PDF/TXT 解析 -> chunkText(500字/重叠50) -> knowledge_chunk 表
                                                              |
用户提问 -> retrieveChunks -> 中文 2-gram + ASCII 词项重叠评分 -> top-k
```

- 存储：分块正文存 MySQL `knowledge_chunk.content`（TEXT）；
- 检索：`SELECT * FROM knowledge_chunk WHERE document_id=?` 后，
  在内存用 `computeSimilarity`（词项交集 / query 词项数）打分；
- 无向量、无嵌入、无语义检索。

局限：
1. 只能匹配**字面词项**，无法理解"机器学习"≈"深度学习"这类语义近义；
2. 文档量大时全表扫描 + 内存打分，O(分块数) 不可扩展；
3. 无 ANN（近似最近邻）索引。

## 二、目标

- 语义检索：query 与 chunk 进入同一嵌入空间，按余弦相似度取 top-k；
- 可扩展：百万级分块下毫秒级响应；
- 平滑迁移：保留现有 MySQL 元数据，向量作为旁路存储。

## 三、向量数据库选型

| 方案 | 自托管 | 适用规模 | 说明 |
|------|--------|---------|------|
| **Chroma** | 是 | 小型 / 原型 | 嵌入式，Python 生态，起步最快 |
| **Milvus** | 是 | 中大型 | 生产级，分布式，HNSW/IVF 索引 |
| **Pinecone** | 云托管 | 任意 | 免运维，按量计费，待外部 API |
| Qdrant | 是 | 中大型 | Rust 实现，过滤能力强 |

毕业项目推荐路径：**Chroma（本地验证）→ Milvus（生产）**。

## 四、嵌入模型选型

| 模型 | 维度 | 部署 | 说明 |
|------|------|------|------|
| `bge-small-zh-v1.5` | 512 | 本地 ONNX | 中文效果好、体积小，推荐起步 |
| `text2vec-base-chinese` | 768 | 本地 | 老牌中文嵌入 |
| OpenAI `text-embedding-3-small` | 1536 | 云 API | 免自托管，待外部 Key |

落地建议：本地用 **ONNX Runtime 加载 `bge-small-zh-v1.5`**，
Java 侧通过 ONNX Runtime Java API 调用，或起一个轻量 Python 嵌入微服务。

## 五、迁移步骤

1. **引入嵌入服务**：新增 `EmbeddingService` 接口
   `float[] embed(String text)`，先接本地 ONNX / 云 API；
2. **写入侧改造**：`chunkText` 产出分块后，调用 `EmbeddingService.embed`，
   把向量写入向量库（collection 含 chunk_id、user_id、document_id、正文）；
3. **检索侧改造**：`retrieveChunks` 改为
   `query -> embed -> 向量库 ANN top-k -> 回查正文`；
4. **混合检索（可选）**：向量分 + 关键词分（现有 `computeSimilarity`）加权融合，
   缓解纯向量对专有名词的召回；
5. **灰度**：先双写（MySQL chunk + 向量库），读路径按开关切换，验证后下线旧检索。

## 六、数据模型（向量库侧）

```json
{
  "id": "<chunk_id>",
  "embedding": [0.012, -0.043, ...],
  "metadata": {
    "user_id": 100,
    "document_id": 1,
    "chunk_index": 3
  },
  "text": "分块正文..."
}
```

**隔离性**：向量库查询时必须带 `user_id` 过滤条件，沿用现有 IDOR 防护，
禁止跨用户检索。

## 七、待外部条件

1. **向量数据库实例**：本地 Chroma 可立刻验证；生产 Milvus / 云 Pinecone 需部署与凭据；
2. **嵌入模型**：本地 ONNX 模型权重需下载；云嵌入 API 需 Key 与计费；
3. **资源**：自托管嵌入推理建议 ≥ 2C4G，Milvus 生产部署建议独立节点。

## 八、与现状的兼容

- 现有 `MySQL LIKE / 词项重叠` 检索在向量库未就绪前**继续作为默认实现**，
  保证完全离线可测（现有 809 后端用例不回退）；
- `EmbeddingService` 与新检索实现通过 `@ConditionalOnProperty` 开关控制，
  外部条件就绪后打开 `kb.retrieval=vector` 即可切换，无需改业务代码。
