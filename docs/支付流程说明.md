# AI Chat 支付流程说明文档

> 版本：v1.0  
> 更新日期：2026-09-17  
> 适用阶段：阶段一 P0 文档类（支付流程与 API 契约说明）

本文档说明 AI Chat 付费服务（会员升级、点数充值）的整体支付流程、对接指引、退款与对账流程，以及当前已实现 / 待实现的支付相关 API 端点。

---

## 1. 总体说明

当前系统采用 **"先绑定支付账户 → 创建订单 → 人工/自动审核 → 发放权益"** 的模式（见后端 `PaymentController` / `PayAccountController`）。本文档在保留现有接口的基础上，补充 **微信支付 / 支付宝** 线上直连的对接规范，作为后续 P1 阶段接入的契约依据。

付费业务对象：

- 会员等级：`FREE → BASIC → PREMIUM`
- 订购字段：`targetLevel`（目标等级）、`durationDays`（订阅天数）、`paymentMethod`（支付方式）
- 订单实体：`PaymentRecord`（含 `reviewStatus` 审核状态）

---

## 2. 支付方式与对接指引

### 2.1 微信支付（JSAPI / Native / 扫码）

对接目标：微信支付 V3 API（`https://api.mch.weixin.qq.com`）。

准备材料：

1. 微信支付商户号（mchid）、APIv3 密钥、商户 API 证书（apiclient_cert.pem / apiclient_key.pem）。
2. 已备案的公众号 / 小程序 AppID，并与商户号完成绑定。
3. 在支付平台后台配置 **支付回调通知地址**：`https://<your-domain>/api/payment/callback/wechat`。

对接要点：

- 统一下单：`POST /v3/pay/transactions/native`（扫码）或 `/v3/pay/transactions/jsapi`（公众号）。
- 请求需使用商户私钥对请求头 `Authorization: WECHATPAY2-SHA256-RSA2048 ...` 进行签名。
- 回调报文使用 APIv3 密钥进行 AES-GCM 解密；必须校验签名与 `resource.ciphertext`。
- 订单号由我方生成（`out_trade_no`），与 `PaymentRecord.id` 或业务订单号一一对应。

### 2.2 支付宝（电脑网站支付 / 手机网站支付）

对接目标：支付宝开放平台（`https://openapi.alipay.com/gateway.do`）。

准备材料：

1. 支付宝商户 PID、AppID、应用私钥 / 支付宝公钥（RSA2）。
2. 签约"电脑网站支付"或"手机网站支付"产品。
3. 配置异步通知地址（notify_url）：`https://<your-domain>/api/payment/callback/alipay`；同步 return_url 可指向前端支付结果页。

对接要点：

- 下单接口：`alipay.trade.page.pay`（PC 网站）/ `alipay.trade.wap.pay`（手机网站）。
- 签名算法：RSA2（SHA256WithRSA）。
- 异步回调需验签，并以 `trade_status = TRADE_SUCCESS / TRADE_FINISHED` 作为入账依据。

> 安全要求：回调接口 **不依赖前端通知**，必须以支付渠道服务器异步通知 + 主动查询订单结果为准；前端"支付成功"弹窗仅作提示，权益发放以后端为准。

## 3. 主流程：订单创建 → 支付 → 回调 → 权益发放

```
用户          前端            后端                支付渠道
 │  选择套餐   │               │                   │
 ├───────────►│               │                   │
 │            │ 1.创建订单      │                   │
 │            ├──────────────►│ POST /api/payment/create
 │            │               │ 2.生成 PaymentRecord(待支付)
 │            │               ├──调用统一下单──────────►│
 │            │               │◄───prepay_id/支付串─────┤
 │            │ 3.返回支付参数  │                   │
 │            │◄──────────────┤                   │
 │  扫码/跳转支付               │                   │
 ├──────────────────────────────────────────────►│
 │            │               │ 4.异步回调通知       │
 │            │               │◄───────notify───────┤
 │            │               │ 5.验签 → 更新订单状态│
 │            │               │ 6.发放会员/点数权益  │
 │            │               │ 7.应答 SUCCESS       │
 │            │               ├───应答──────────────►│
 │            │ 8.前端轮询/跳转结果页                │
 │            │◄──────────────┤                   │
```

关键步骤说明：

1. **订单创建**：调用 `POST /api/payment/create` 或 `POST /api/payment/membership/upgrade`。后端强制以登录用户为订单归属（忽略客户端传入的 `userId`），生成待支付订单。
2. **发起支付**：后端调用支付渠道统一下单接口，返回 `prepay_id`（微信）或支付跳转 URL（支付宝）。
3. **用户支付**：用户在微信 / 支付宝侧完成付款。
4. **异步回调**：支付渠道主动请求我方回调地址。后端必须：
   - 校验签名 / 解密报文；
   - 校验金额、商户号、订单号与本地一致；
   - 幂等处理（同一回调重复到达不得重复发放权益）；
   - 立即应答渠道（微信返回 `200` 且 body `SUCCESS`，支付宝返回 `success`），再做后续业务；
   - 更新 `PaymentRecord.reviewStatus` 为已支付，并发放会员等级 / 点数。
5. **前端结果页**：前端通过 `GET /api/payment/{id}` 轮询订单状态，或跳转至 `/upgrade` 结果页展示。

## 4. 退款流程

适用场景：服务故障、权益未到账、重复支付、合规要求（如未成年人退款）。

流程：

1. 用户 / 客服发起退款申请（当前通过工单 / 客服通道，后端暂未开放用户自助退款接口）。
2. 管理员在后台调用退款接口（待实现，见第 6 节），后端向支付渠道发起退款：
   - 微信：`POST /v3/refund/domestic/refunds`
   - 支付宝：`alipay.trade.refund`
3. 支付渠道异步返回退款结果（退款回调地址：`/api/payment/refund/callback/{wechat|alipay}`）。
4. 后端更新订单状态为"已退款"，回收已发放的会员权益（或按剩余天数折算），记录审计日志（`@Audited(action="REFUND_PAYMENT")`）。
5. 退款到账时效：微信 1~3 个工作日，支付宝 1~7 个工作日，具体以渠道为准。

注意事项：

- 退款金额不得超过原订单金额；部分退款需记录累计退款金额，避免重复退。
- 已开票 / 已消耗点数的订单，按剩余未消耗部分退款。
- 所有退款操作必须留痕，含操作人、时间、原因、渠道退款单号。

## 5. 对账流程

每日 T+1 对账，保证我方订单与支付渠道流水一致：

1. **拉取渠道对账单**：定时任务（建议凌晨执行）调用：
   - 微信：下载 `https://api.mch.weixin.qq.com/v3/bill/tradebill`（交易账单）与 `.../fundflowbill`（资金账单）。
   - 支付宝：`alipay.data.dataload.bill.downloadurl.query` 获取账单下载地址。
2. **逐笔核对**：以 `out_trade_no`（我方订单号）为主键，比对：
   - 渠道交易金额 vs 本地订单金额；
   - 渠道交易状态 vs 本地 `reviewStatus`；
   - 退款金额是否一致。
3. **差异处理**：
   - **长款**（渠道已收款、本地未入账）：触发主动查单 `POST /api/payment/query/{id}`，补发权益并告警。
   - **短款**（本地已入账、渠道未收款）：冻结权益，通知客服人工核查。
   - **金额不符**：挂起订单，人工介入。
4. **生成对账文件**：输出每日对账差异报表，归档保留至少 3 年（合规要求）。

## 6. 支付相关 API 端点

### 6.1 已实现端点（当前后端 `PaymentController` / `PayAccountController`）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/payment/create` | 登录 | 创建支付订单（body 需含 `versionType`、`durationDays`；后端强制覆盖 `userId`） |
| POST | `/api/payment/{id}/review` | 管理员 | 审核支付订单（body 含 `reviewStatus`） |
| GET | `/api/payment/{id}` | 登录（仅本人/管理员） | 查询单笔订单详情 |
| GET | `/api/payment?page=&size=&reviewStatus=` | 管理员 | 分页查询全部订单 |
| GET | `/api/payment/user/{userId}` | 管理员 | 查询指定用户的订单列表 |
| GET | `/api/payment/pending` | 管理员 | 待审核订单列表 |
| POST | `/api/payment/membership/upgrade` | 登录 | 发起会员分级升级（body：`targetLevel`、`durationDays`、`paymentMethod`） |
| POST | `/api/pay-account/bind` | 登录（本人） | 绑定支付账户（`accountType`、`accountNumber`、`accountName`） |
| POST | `/api/pay-account/verify` | 登录 | 校验绑定账户（`id`、`verificationCode`） |
| DELETE | `/api/pay-account/{id}` | 登录 | 解绑支付账户 |
| GET | `/api/pay-account/user/{userId}` | 登录（本人） | 查询当前用户绑定的支付账户 |
| GET | `/api/pay-account/user/{userId}/has-any` | 登录（本人） | 是否已绑定任意支付账户 |

> 说明：现有 `/api/payment/create` 与 `membership/upgrade` 为 **模拟/审核制** 下单，并未真正调用微信/支付宝统一下单接口。下表"待实现"项用于补齐线上直连闭环。

## 7. 安全注意事项

1. **回调必须验签**：微信 V3 校验 HTTP 头签名并 AES-GCM 解密；支付宝使用支付宝公钥验签。严禁仅凭 HTTP 参数判定支付成功。
2. **金额强校验**：以本地订单金额为准，回调金额不一致一律拒绝并告警。
3. **幂等发放**：权益发放逻辑必须幂等，同一 `out_trade_no` 多次回调不得重复加会员 / 加点数。
4. **订单归属**：所有查询 / 操作接口强制 `AuthContext.requireUserId()`，禁止信任客户端传入的 `userId`（现有 `PaymentController` / `PayAccountController` 已修复）。
5. **敏感信息脱敏**：支付账号、银行卡号在日志与接口返回中必须脱敏（仅保留后 4 位）。
6. **密钥管理**：商户私钥、APIv3 密钥、支付宝公钥等通过环境变量 / 配置中心注入，禁止写入代码库或前端。
7. **审计留痕**：创建、审核、退款等动作通过 `@Audited` 注解落审计日志（`CREATE_PAYMENT` / `REVIEW_PAYMENT` / `REFUND_PAYMENT`）。
8. **HTTPS 强制**：回调地址必须为 HTTPS，禁止使用内网 HTTP 接收渠道通知。
9. **防重放**：回调处理记录已处理的 `transaction_id`，短时间内重复通知直接应答成功但不重复入账。
10. **前端不可信**：前端"支付成功"仅作提示，权益以后端回调 / 主动查单结果为准；严禁前端直接调用"发放权益"接口。
