# ai-chat-graduation QA 系统测试报告

## 一、结论

本次对 ai-chat-graduation 本地开发环境（前端 5187 / 后端 Spring Boot 8080 / MySQL 3306）执行了以认证与注册为核心的系统测试，并在发现 admin 种子口令缺陷后完成收口复验。

**发布判断：有条件放行（conditional_go）。** 修复管理员口令缺陷后，「注册 → 登录（含管理员双入口）取得 JWT → 带 token 访问受保护资源 → 参数校验 → 越权防护」核心链路**全部通过**，无开放 S1/S2，P0 阻断集合为空。剩余未覆盖（Redis/Prometheus 本机未安装、无确认对话模型、兄弟代理在改模块）属于环境与并行任务边界，不构成已验证范围内的阻断项。

本轮共 12 个用例：**通过 11、阻塞 1（TC-011 依赖本机未安装的 Redis）、失败 0**；正式缺陷 1 个，**已修复并关闭（BUG-001，S3/P3）**。

## 二、需求口径与资料冲突

- 接口契约以源码为准：注册 `POST /api/user/register`、登录 `POST /api/user/login`、管理员 `POST /api/admin/login`。
- **已解决的资料冲突**：任务给定 `admin/123456` 初测返回 401，经查为种子口令明文存储（详见已关闭缺陷）。修复并改 bcrypt 哈希后，admin 双入口登录均 200。
- 登录高峰现象（测试初期登录 POST 不返回、低谷恢复）经日志判断为并行 E2E 占满 Tomcat worker 线程排队，非产品缺陷，不计入结果。

## 三、业务链路与范围

本轮聚焦认证与注册决策级链路：健康检查、新用户注册（合法/非法/重名）、登录成功与失败、JWT 鉴权、垂直越权。收口阶段补跑了管理员登录回归并启动本地 Ollama。

不覆盖：Redis 依赖的失败计数/账户锁定、Prometheus 指标、AI 对话端到端（无确认对话模型）、支付真实回调、移动端兼容、兄弟代理在改模块。

## 四、风险排序

## 六、缺陷与收口

**BUG-001（S3/P3，已 closed）：admin 种子口令以明文存储，文档给定管理员凭据无法登录。**
- 根因：user 表 admin(id=63) password 为明文 `123456`，登录走 DelegatingPasswordEncoder.matches 必然 401；原管理员登录另有手写明文 equals 兼容分支。
- 修复：① 管理员登录统一改为 passwordEncoder.matches（兼容 {bcrypt} 前缀与裸 $2a$，明文必然不匹配）；② 对应单测移除明文兼容用例、新增 bcrypt 正确匹配与明文不匹配两用例（Admin 相关 21 用例全过）；③ 库中 id=63 口令更新为 bcrypt 哈希。
- 我方独立复验：`/api/user/login admin/123456`→200+token；`/api/admin/login admin/123456`→200；错误密码→401；demo_alice→200。

无 S1/S2；P0 阻断集合为空，与发布决策 `blocking_bug_ids=[]` 一致。
